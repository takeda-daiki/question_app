# Step 6：ログインして、最初の疑問を保存する

この段階では、メールとパスワードの登録・ログイン・ログアウト、タイトルだけのカード登録、未解決カードの一覧を使えます。分類・編集・検索などは後続の段階で追加します。

## 1. パソコンで起動する

Node.js 22.12以上の対応するLTS版を用意してください。依存関係は `pnpm-lock.yaml` で固定しています。初回のみ `npm install -g pnpm@11.19.0` を実行します。

リポジトリのフォルダで、次を実行します。

```sh
pnpm install --frozen-lockfile
```

`.env.example` をコピーし、`.env.local` という名前で同じフォルダに置きます。Supabaseの対象プロジェクトでConnectからProject URLを、API KeysからPublishable keyを確認し、2項目を置き換えます。

```dotenv
VITE_SUPABASE_URL=https://あなたのプロジェクト.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_あなたの公開用キー
```

今回は `sb_publishable_` で始まるキーを使います。Secret key、service_role、データベースのパスワードは使いません。`VITE_` の値はブラウザーに配信されるため、秘密情報を入れないでください。`.env.local` はGitの保存対象から除外されています。

```sh
pnpm dev
```

表示された `http://127.0.0.1:5173` をブラウザーで開きます。設定を変えた場合は起動し直します。HTMLをダブルクリックして開く方法では動作しません。

## 2. Step 5のアクセス制限を確認する

テーブルを作成しただけでは不十分です。Step 5.5-BのRLS・アクセス許可設定まで完了している必要があります。`sql/check-step5.sql` は状態を見るだけのSQLです。SupabaseのSQL Editorで実行できます。

- `qm_cards` の `rls_enabled` が `true`。
- `SELECT` と `INSERT` のポリシーがあり、ログインした本人の `user_id` だけを許可している。
- `authenticated` にSELECTとINSERTが許可され、`anon` には許可されていない。

チェック結果を見るだけでは他ユーザーへのアクセス拒否の実証にはなりません。公開前には、異なる2アカウントでそれぞれ保存し、相手のカードが表示されないことも確認します。テスト用ブラウザー確認は通信を模擬しており、実際のRLSの検証は別途必要です。

既存アプリとSupabaseを共用しています。この実装は既存テーブルやプロジェクト共通の認証設定を変更しません。テーブル名は `public.qm_cards` を使用します。

## 3. ログインする

同じSupabaseプロジェクトに既にメール・パスワードのアカウントがある場合は、そのアカウントでログインできます。認証ユーザーはプロジェクト内で共通です。

新規の場合は「初めての方はこちら」から作成します。メール確認が有効な場合は、届いた確認メールのリンクを開き、その後このアプリでログインします。アプリ側は確認完了前にカードを表示しません。

確認メールの行き先は既存プロジェクトの認証設定に従います。既存アプリと共用しているため、Site URLを不用意に上書きしないでください。既存設定の変更が必要なら影響を確認してから行います。今回の実装にはパスワード再設定画面は含みません。

## 4. 最初の成功を確認する

1. ログインする。
2. 「＋ 疑問を追加」を押す。
3. 「ベイズ推定とは？」と入力し「保存する」を押す。
4. 一覧に表示されることを確認する。
5. ブラウザーを再読み込みし、同じ疑問が残ることを確認する。
6. ログアウトし、一覧が消えることを確認する。
7. 再びログインし、記録が表示されることを確認する。

保存に失敗した場合、入力は消えません。通信断などで応答だけ失われた場合にも、同じ入力の再試行では同じカードIDを使用します。ブラウザーを閉じると未保存の入力は失われます。

## 5. エラーが出たら

| 表示・症状 | 確認すること |
| --- | --- |
| 接続設定をしましょう | `.env.local` の2項目を入力し、起動し直す |
| ログインできない | メール・パスワード、メール確認、通信状態 |
| 一覧・保存に失敗する | Step 5.5-B、接続先、`qm_cards` の存在 |
| 確認メールが届かない | 迷惑メール、送信制限、Supabaseのメール設定 |

## 開発者向け：構造と確認

- `src/auth/`：登録・ログイン画面
- `src/cards/api.ts`：カードの読込・保存
- `src/cards/CardList.tsx`：一覧と追加ダイアログ
- `src/lib/supabase.ts`：接続設定
- `src/App.tsx`：ログイン状態による画面切替
- `tests/`：PC・スマートフォンの操作テスト（通信は模擬）

```sh
pnpm build
pnpm exec playwright install chromium
pnpm test
```

テストは専用の架空URLに接続を差し替えるので、本番データへ書き込みません。本番接続でのログイン・保存・RLSは実アカウントによる確認が必要です。

`pnpm build` で生成される `dist/` が公開用です。ホスティング先を決めたら、そこに同じ2つの公開用環境変数を設定してビルドします。今回、自動デプロイやデータベース変更は行いません。

公式資料：[Viteの起動手順](https://vite.dev/guide/)・[Supabaseの公開用キー](https://supabase.com/docs/guides/getting-started/api-keys)・[メールとパスワードの認証](https://supabase.com/docs/guides/auth/passwords)
